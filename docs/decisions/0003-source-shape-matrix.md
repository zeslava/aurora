# 0003 — Фикстура задаётся осями формы источника, а не сериалом

Дата: 2026-08-02. Развивает [0001](0001-hls-copy-segmentation.md) и [0002](0002-ffmpeg-port.md).

## Контекст

Три бага подряд прошли мимо зелёных тестов по одной и той же причине: **фикстура была
здоровее реального релиза**.

1. Рассинхрон карты и нарезки — не воспроизводился на равномерном GOP.
2. Нулевой сегмент без видео — не воспроизводился на потоке, где у всех пакетов есть DTS.
3. Сегменты рана не с начала файла уезжали на 2–3 c — не воспроизводился на ране с нуля.

`testsrc + libx264` по умолчанию даёт ровный GOP, полные таймстемпы и один ран с нуля. На
таких данных неправильная нарезка неотличима от правильной. Каждый раз это выглядело как
«починили один сериал — сломался другой», хотя сериал ни при чём.

Замеры библиотеки показывают, чем реальные файлы отличаются друг от друга:

| | контейнер | видео | таймстемпы | GOP |
|---|---|---|---|---|
| Breaking Bad (LostFilm 1080p) | mkv | h264 | 2 пакета с `dts=N/A` | рваный, 1.2–10.4 c |
| Gossip Girl (WEB-DL 720p) | mkv | h264 | 1 пакет с `dts=N/A` | частый, 0.04–1.0 c |
| Scooby Doo (DVDRip) | avi | mpeg4 | `pts` нет вовсе | рваный, 0.9–10.4 c |

Оси «кодек видео» и «кодек аудио» в коде представлены (`StreamProfile`). Осей «форма
таймстемпов» и «форма GOP» не было нигде — ffprobe их видит, а мы выбрасывали.

## Решение

1. `src/testkit.rs` — оси как типы (`TimestampForm`, `GopForm`, `VideoForm`, `AudioForm`) и
   `Shape::matrix()`: точки, покрывающие реальную библиотеку плюс контрольная «удобная»
   форма. Файлы генерируются синтетикой, в репозиторий ничего не кладётся: `-bf 3
   -x264opts b-pyramid=normal` даёт `dts=N/A` в начале, avi с B-кадрами — отсутствие `pts`.
2. `Shape::build` проверяет, что сгенерированный файл **действительно** обладает заявленной
   формой. Без этого матрица вырождается молча: смена версии ffmpeg — и все фикстуры снова
   «чистые», тесты зелёные, покрытия нет.
3. `testkit::assert_playable` — один чеклист для всех форм и всех стратегий нарезки:
   видеопакеты есть; SPS/PPS на месте; параметры видео не меняются между сегментами; длина
   по видеодорожке = EXTINF; стык N/N+1 без дыры и нахлёста.
4. `server::tests::every_source_shape_produces_playable_segments` — матрица в обычном прогоне.
   `real_library_conformance` (`#[ignore]`) — разведка по настоящей библиотеке, по одному
   файлу на группу `(video_codec, audio_codec, pix_fmt)`.

## Что сломается, если сделать «очевидным» способом

- **Чинить под файл.** Правка «чтобы заработал этот сериал» не двигает матрицу, и следующий
  файл той же формы сломается снова. Правило: новая поломка = новая ось или новая точка в
  `Shape::matrix()`, и только потом фикс.
- **Мерить длительность сегмента по `format=duration`.** Её держит аудио. Сегмент, из
  которого выброшено всё видео, по ней выглядит здоровым — так баг №2 обошёл и тесты, и
  метрику `segment_drift` (она считала то же самое и показывала `checked: 128, mismatched: 0`).
- **Считать тест на `to_args()` проверкой поведения.** `encode_run_keeps_absolute_timestamps`
  фиксировал сдвиг `-force_key_frames` на `start_time` — и фиксировал неправильное значение.
  Тесты на аргументы защищают только от случайной перестановки флагов; семантику проверяет
  запуск.
- **Гонять conformance на общем `/tmp`.** Ключ кэша — отпечаток файла, не версия кода, так
  что прогон подхватывает сегменты, нарезанные прошлой версией. У `HlsManager` поэтому есть
  `with_root`, и каждый тестовый `AppState` получает свой корень.
- **Считать conformance покрытием.** Его роль — найти форму, которой нет в матрице. Нашлась —
  ось переезжает в `Shape::matrix()` и дальше держится синтетикой, без зависимости от того,
  что лежит на диске.

## Найдено этим механизмом

- `-ss 0` на выходе выбрасывает видео из copy-сегмента (см. `ffmpeg::CopySegment`). Матрица
  ловит на `lostfilm_h264_ac3`; контрольная форма `clean_h264_aac` проходит.
- `-force_key_frames` под `-start_at_zero` отсчитывает `t` от начала рана, а не файла. Сдвиг
  на `start_time` делал выражение всегда ложным, x264 резал по своему GOP: 8.4/4.1/7.8/8.8 c
  вместо обещанных картой 6.0. Нашёл `real_library_conformance` на `mpeg4/ac3/yuv420p`.
