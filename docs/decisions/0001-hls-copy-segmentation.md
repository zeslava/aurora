# 0001 — Нарезка HLS для copy-профилей: посегментный запуск, а не муксер

Дата: 2026-08-02. Подробный разбор с числами: [`РАЗБОР_ПОЛЕТОВ.md`](../../РАЗБОР_ПОЛЕТОВ.md).

## Контекст

Номер сегмента обязан быть чистой функцией от файла и профиля: плейлист отдаётся целиком
сразу, сегменты генерируются лениво, разные раны ffmpeg должны давать для одного номера один
и тот же диапазон. Карта (`SegmentMap`) считается по keyframes из ffprobe и хранится в БД.

Для профилей с `-c:v copy` нарезкой занимался hls-муксер (`-hls_time`). Он режет по
собственному расписанию — первый keyframe на/после `старт_рана + n*hls_time`, отсчёт
кумулятивный и относительный к старту **каждого** рана. Карта и реальные резы расходились:
на одном файле 469 сегментов в карте против 640 у ffmpeg, 2.5 c расхождения на 4-м сегменте
и 407 c на 300-м. Плеер клал сегменты не туда, в буфере появлялись дыры, воспроизведение
подвисало каждые 5–10 секунд. В логах — ничего: ffmpeg успешен, HTTP 200.

## Решение

1. Контейнер сегментов зависит от профиля: fMP4 только там, где видео перекодируется, для
   copy-профилей — MPEG-TS (не нужен init-сегмент, одинаков для всех ранов).
2. Для copy-профилей границу задаёт не муксер, а сам вызов: один ffmpeg на сегмент,
   приблизительный вход (`-ss` до `-i` с запасом 20 c), точная граница выходным `-ss`,
   длина через `-t`, абсолютные таймстемпы через `-output_ts_offset`
   (`transcoder::run_copy_segments`, аргументы — `ffmpeg::CopySegment`).
3. Равномерная сетка для copy-профиля запрещена: `SegmentMap` — это enum
   `Keyframes | Grid`, а нарезчик copy-профиля принимает только `Boundaries` из
   `Keyframes`. Если keyframes прочитать не удалось, `segment_map_for` откатывается на
   профиль с перекодированием видео.
4. Ключ кэша сегментов включает отпечаток файла (путь + размер + mtime).

## Что сломается, если сделать «очевидным» способом

- **Вернуть `-hls_time` для copy-профилей.** Муксер не умеет резать по заданному списку точек;
  расхождение с картой накапливается и проявляется тихими подвисаниями в середине серии.
- **Взять муксер `segment` с `-segment_times`.** Работает только для рана с начала файла:
  после входного `-ss` старт рана уезжает на более ранний keyframe, а `-segment_times`
  считается от старта рана, не от начала файла.
- **Достроить карту по равномерной сетке, когда нет индекса keyframes.** Гарантированный
  рассинхрон — при `-c:v copy` резать в произвольной точке нельзя.
- **Добавить `-avoid_negative_ts make_zero` в ран с перекодированием.** Обнулит таймлайн
  рана, стартующего не с начала файла.
- **Обрезать транскодированный поток по байтам.** Ломает MP4-контейнер; длина задаётся `-t`.

## Как это удерживается

- `server::tests::copy_profile_segments_match_playlist_durations` — ffprobe-ит выданные
  сегменты и сверяет с EXTINF. Фикстура с **неравномерными** keyframes: на ровном GOP оба
  правила нарезки совпадают, и тест прошёл бы, не заметив бага.
- Тип: сетку нельзя передать в `run_copy_segments`.
- Метрика `segment_drift` в `/api/metrics` — см. [0002](0002-ffmpeg-port.md).
