# 0010 — Docker-образ: ffmpeg из apk, без лишних пакетов

Дата: 2026-10-18.

## Контекст

Образ раздаётся друзьям через ghcr.io (`.github/workflows/docker.yml`, amd64 + arm64). На
`alpine` + `apk add ffmpeg` он весит ~160 МБ, из них ~124 МБ — 120 пакетов зависимостей
ffmpeg (x265, aom, svt-av1, X11, vulkan) ради энкодеров, которые Aurora не вызывает.

Пробовали собрать свой ffmpeg с урезанным набором компонентов: все встроенные демуксеры и
декодеры, на выходе только то, что называет `ffmpeg.rs`. Получилось 54 МБ, тесты проходили.
Отказались: этап компиляции в `Dockerfile` и список `configure`, который надо держать в
синхроне с рецептами, не стоят 110 МБ для образа, который раз в релиз скачивают несколько
человек.

## Решение

1. **ffmpeg — пакет из apk** в финальном слое.
2. **Других пакетов нет:** sqlite вшит через sqlx, корни TLS для TMDB — через reqwest
   (`webpki-roots`), `chrono::Local` не используется, `wget` для healthcheck есть в busybox.
3. **Бинарь собирается со `strip`**, база — `alpine:3.22`, а не плавающий `latest`.

## Что сломается, если сделать «очевидным» способом

- **Собрать свой ffmpeg ради размера.** Любой новый фильтр, энкодер или муксер в
  `ffmpeg.rs` придётся добавлять и в `configure`, а обычный `cargo test` идёт на системном
  ffmpeg и пропуск не поймает — образ упадёт только у пользователя. Ловушка, на которой это
  всплыло: пакетный ffmpeg молча игнорирует приватную опцию чужого муксера, урезанный падает
  с `Option not found` (так было с `-reset_timestamps` при `-f mp4`, флаг из рецепта убран).
- **Вернуть `alpine:latest`.** Смена мажорной версии Alpine меняет и версию ffmpeg из apk —
  рецепты в `ffmpeg.rs` проверены на 6.1, переход на новую версию должен быть явным.
