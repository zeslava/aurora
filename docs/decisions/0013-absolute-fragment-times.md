# 0013 — Абсолютный `tfdt` во фрагментах fMP4

Дата: 2026-11-01. Развивает [0003](0003-source-shape-matrix.md) и [0011](0011-vaapi-video-encode.md).

## Контекст

Жалоба: «звук идёт вперёд картинки» на `De.l'autre.cote.du.periph.2012…XviD.AC3.avi` в Firefox
на iPadOS. В VLC тот же файл играет ровно. Первый блок AC3 в этом avi (68 431 байт, 1,2 c) не
декодируется, поэтому в ране с начала файла звук начинается на 1,2 c позже видео.

hls-муксер считал `tfdt` каждой дорожки от её первого пакета, а разницу записывал в edit list
`init.mp4`:

| сегмент | `tfdt` видео | `tfdt` звука |
|---|---|---|
| 61, ран с начала | 366,0 c | 364,8 c |
| 400, ран с начала | 2400,0 c | 2398,8 c |
| 700, ран с середины | 0 c | 0 c |

ffprobe применяет edit list и показывал ровные таймстемпы. hls.js edit list не разбирает и берёт
`tfdt`. Ран с середины получал в init пустой edit на всю пропущенную часть (4200 c), и init
зависел от того, какой ран опубликовал его первым. В коде при этом стояло обратное утверждение.

## Решение

1. `-hls_segment_options movflags=+frag_discont` в `ffmpeg::HlsEncodeRun`: `tfdt` абсолютный, в
   edit list нет пустых записей, init одинаков у всех ранов. Проверено на ffmpeg 6.1 и 9.0.
2. `aresample=async=1:first_pts=0` в ране с начала файла: тишина закрывает начало звука, и буфер
   плеера не начинается с дыры.
3. Ось `AudioStartForm` в `Shape::matrix()` и проверка сырого `tfdt` в `assert_playable`.
4. `SEGMENT_RECIPE_VERSION` в ключе кэша: старые сегменты не склеятся с новым init.

## Что сломается, если сделать «очевидным» способом

- **Мерить синхрон через ffprobe.** Он применяет edit list и показывает, что всё ровно, пока
  плеер играет со сдвигом. Правду показывают только сырые боксы.
- **`first_pts=0` в ране с середины.** Под `-copyts` это тишина от нуля файла до точки старта.
- **Только тишина, без `frag_discont`.** Синхрон рана с начала починится, но `tfdt` рана с середины
  останется от нуля, а init будет зависеть от рана.
- **`use_editlist=0` вместо `frag_discont`.** Edit list исчезает, но `tfdt` остаётся от нуля: разница
  между дорожками просто теряется.

## Границы

- Фрагменты с B-кадрами сохраняют в init `media_time` ненулевым (два кадра). Плеер, который его не
  учитывает, покажет видео позже звука примерно на 0,08 c.
- Как WebKit на iPadOS обрабатывает edit list, не проверено: воспроизвести его на Linux нельзя.
- Каталоги сегментов со старым ключом остаются в temp-директории сервера до её очистки.
