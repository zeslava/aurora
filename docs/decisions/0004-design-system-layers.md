# 0004 — Дизайн-система: три слоя токенов и режимы ввода как первый класс

Дата: 2026-08-02. Правила и справочник — в [`docs/design-system.md`](../design-system.md).

## Контекст

Фронтенд собран без CSS-фреймворка: токены в `:root` плюс небольшой набор общих классов,
остальное — scoped-стили компонентов. Это работало, но система расползалась в трёх местах.

1. **Токены описывали только палитру и шкалы.** Не было слоёв «глубина» и «движение» и не
   было промежуточных ступеней затемнения. В коде появлялись голые `z-index: 50`,
   `rgb(0 0 0 / 0.28)`, `rgb(0 0 0 / 0.6)`, `rgb(0 0 0 / 0.9)` — каждое значение подобрано
   на глаз под свой экран, и сравнить их между собой было невозможно.
2. **Одинаковые блоки жили в двух местах.** `.movie-bg` в `MovieDetail` и `.series-bg` в
   `SeriesDetail` совпадали посимвольно вместе с гашением подложки шапки; `.header__inner`
   был объявлен в трёх файлах; полоса прогресса существовала дважды — общий `.progress` и
   собственный `.tile__progress` в плитке.
3. **`--focus-ring` использовался не по назначению.** `.episode--resume` красил им рамку
   «продолжить с этой серии» — состояние контента, а не фокуса.

## Решение

1. **Три слоя токенов.** Палитра (`--gray-700`, `--sky-500`, …) → семантика (`--surface`,
   `--scrim-media`, `--z-modal`, `--text-on-media`) → локальные переменные компонента для
   вычисляемых значений (`--ph-hue`). Разметка берёт только средний слой.
2. **`src/tokens.css` — отдельный файл.** Единственное место, где разрешены сырые цвета и
   размеры; `index.css` импортирует его и содержит только базу и общие классы. Граница
   проведена файлом, потому что её умеет проверять линтер, а комментарий — нет.
3. **Дубли вынесены в компоненты**, не в классы: `AppHeader`, `DetailBackdrop`, `Modal`,
   `Section`/`Row`, `ScreenMessage`. Класс общий, только когда потребителей три и больше.
4. **Режимы ввода — часть системы.** Мышь, D-pad и Magic Remote описаны в правилах вместе со
   следствиями; `--focus-ring` закреплён исключительно за фокусом, а метка «продолжить»
   выделена в `.marker-resume` на `--accent`.
5. **stylelint вместо договорённости.** Запрещены сырые цвета, `px`-отступы и размеры шрифта,
   числа в `z-index`, посторонние брейкпоинты. Входит в `npm run build`.

## Что сломается, если сделать «очевидным» способом

- **Разрешить сырые значения «в одном месте, здесь так нагляднее».** Именно так система и
  расползлась в прошлый раз: каждое такое место выглядит безобидно, а вместе они дают восемь
  несравнимых затемнений. Ослабление правила в конфиге снимает защиту со всего проекта —
  исключение оформляется построчным `stylelint-disable-next-line` с причиной.
- **Задать размеры в `px`.** Общий масштаб интерфейса — это `html { font-size }`: 16px на
  ноутбуке, 22px в ТВ-режиме. Всё в `rem` тянется за ним автоматически, всё в `px` остаётся
  мелким на телевизоре — то есть ровно там, где приложение и смотрят.
- **Перейти на range-нотацию медиа-запросов (`width >= 640px`).** Браузер webOS её не
  понимает и отбрасывает весь блок: на телевизоре молча ломается адаптив.
- **Красить состояния контента в `--focus-ring`.** Под Magic Remote обводка фокуса гасится
  глобально — вместе с ней исчезает и подсказка «продолжить», причём только на телевизоре.
- **Переопределять общий класс из scoped-стилей компонента.** Работает, только если элемент
  объявлен в разметке этого же компонента. После выноса шапки в `AppHeader` правила для
  `.header__inner` из `Library.svelte` перестали применяться — такие правила переезжают
  в `index.css` вместе с элементом.
- **Считать `svelte-check` проверкой стилей.** Он не видит ни сырых цветов, ни мёртвых
  классов: расхождения ловит только `npm run lint:css`.
