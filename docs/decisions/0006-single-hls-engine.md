# 0006 — Один HLS-движок на всех платформах: hls.js, нативный HLS только без MSE

Дата: 2026-08-06.

## Контекст

Жалоба: «открыл продолжить серию — повисло, а потом просто переключилось на следующую».
Серверные логи (`019fceae-2f1c…5f1d`, 242 сегмента) дали точный таймлайн:

| время | что в логе |
|---|---|
| 12:56:36 | плейлист, `init.mp4`, `segment00000`, `segment00001` |
| 12:56:37.9 | **второй** `init.mp4`, прыжок на `segment00159` (≈954 c — сохранённая позиция) |
| 12:56:38 → 12:57:14 | сегменты 159…241 по 0.3–0.5 c каждый: 8 минут видео за 38 секунд |
| 12:57:14 | последний сегмент → автопереход на следующий эпизод |

Сервер отработал штатно: все сегменты отданы, почти все — из кэша, ошибок нет.
Единственные WARN — восстановимые ошибки декодера на битых пакетах DVB-исходника.

Ключ к диагнозу — `segment00000` перед прыжком на 159. У hls.js со `startPosition`
нулевого сегмента не бывает: движок сам начинает загрузку с нужного фрагмента. Старт
с нуля и последующий seek — почерк нативной ветки. Подтверждение от обратного: за
40 секунд зависания в логах нет ни одного следа обработчика ошибок hls.js.

## Что было не так

Ветка выбиралась по `video.canPlayType('application/vnd.apple.mpegurl')` **впереди**
`Hls.isSupported()`, поэтому webOS уходил в нативный HLS. Две ветки расходились ровно
в том, что в этом плеере ломается чаще всего:

- **стартовая позиция.** hls.js: `startPosition` в конструкторе. Нативная ветка: старт
  с нуля, затем `currentTime = start` на `loadedmetadata` — то есть в буфер сперва
  попадают сегменты с таймстемпами ~0, а после seek'а поверх ложится ран `start=159`
  с абсолютными таймстемпами ~954.
- **восстановление после ошибок.** Весь накопленный аппарат (`fatalCount`, разбор
  устаревшего плейлиста по 404, `recoverMediaError`) жил только в hls.js-ветке. На
  телевизоре его не было вовсе — отсюда «висит молча», а затем playhead выдёргивает
  в конец таймлайна и срабатывает `ended`.

Из-за этого весь опыт, добытый отладкой в десктопном Chrome, до телевизора не доезжал,
а баги воспроизводились только на устройстве, где консоль доступна лишь через
`ares-inspect`.

## Решение

hls.js — основной движок везде, где есть MSE, включая webOS и Tizen. Нативный HLS
остаётся фолбэком для браузеров без MSE (старая Safari на iOS):

```js
if (!Hls.isSupported() && video.canPlayType('application/vnd.apple.mpegurl')) {
```

Один движок — один контракт стартовой позиции и одна обработка ошибок.

## Границы

Платформенные развилки, не касающиеся бизнес-логики, остаются как есть и проблемой
не являются: hash-роутинг в упакованном `.ipk` (`router.svelte.ts`), экран ввода адреса
сервера (`App.svelte`), масштаб шрифта на 4K-панели (`tvMode.ts`), D-pad и Magic Remote
(`spatialNavigation.ts`, `pointerMode.ts`). Правило: развилка допустима для ввода,
навигации и вёрстки; путь воспроизведения должен быть один.

Ни одна ветка плеера не покрыта тестами — матрица `Shape` в `testkit.rs` проверяет
сегменты на сервере, а расходились ветки в клиенте. Это и есть причина, по которой
ошибку нашли только по продовым логам.
