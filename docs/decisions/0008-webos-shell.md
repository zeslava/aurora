# 0008 — webOS-приложение — оболочка, SPA приходит с сервера

Дата: 2026-10-10.

## Контекст

`.ipk` содержал собранную SPA (`npm run build` с `VITE_BASE=./`), которая ходила к серверу
Aurora по HTTP. Интерфейс на телевизоре был копией фронтенда на момент сборки `.ipk`: любая
правка UI — даже переименование кнопки — доходила до ТВ только после пересборки и
`ares-install`. Сервер и ТВ при этом легко расходились по версиям.

## Решение

1. **`.ipk` — тонкая оболочка** (`frontend/webos/index.html`): хранит адрес сервера в
   `localStorage`, проверяет `/health` и делает `location.replace` на адрес сервера. Дальше
   работает та же SPA, что и в браузере.
2. **`scripts/build-webos.sh` фронтенд не собирает.** В staging попадают только оболочка,
   иконки и `appinfo.json`. `AURORA_SERVER_URL` (или первый аргумент) — адрес по умолчанию,
   подставляется вместо `__AURORA_SERVER_URL__`; без него адрес вводится в приложении.
3. **Обновление UI = обновление сервера.** `webos-deploy` нужен только при изменении самой
   оболочки, иконок или манифеста.

## Что сломается, если сделать «очевидным» способом

- **Снова упаковать SPA в `.ipk`.** Вернётся расхождение версий: исправление на сервере не
  видно на ТВ, пока кто-то не переустановит приложение.
- **Проверять сервер обычным `fetch` (без `no-cors`).** Оболочка живёт на `file://`, запрос
  кросс-доменный — без CORS-заголовков на `/health` он падает даже у живого сервера.
  Непрозрачного ответа достаточно: важен сам факт, что сервер ответил.
- **Убрать минимальное время экрана подключения.** Если сервер отвечает, переход случается
  мгновенно, и кнопку «Сменить сервер» нажать невозможно — сменить адрес можно будет только
  переустановкой.
- **Сохранять адрес только после успешного подключения.** Сервер выключен — пользователь при
  каждом запуске набирает адрес пультом заново.
- **Подключаться по старой попытке после «Сменить сервер».** Опоздавший ответ `ping` уведёт
  с экрана ввода; поэтому у каждой попытки свой номер, и устаревшие игнорируются.
