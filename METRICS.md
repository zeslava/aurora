# Метрики Aurora

Система метрик позволяет отслеживать использование ресурсов сервера в реальном времени.

## Эндпоинт метрик

### GET /api/metrics

Возвращает JSON с метриками процесса и системы.

**Пример ответа:**

```json
{
  "process": {
    "memory_bytes": 52428800,
    "memory_mb": 50.0,
    "cpu_percent": 2.5,
    "open_files": null,
    "uptime_seconds": 3600,
    "threads": null
  },
  "system": {
    "total_memory_bytes": 17179869184,
    "total_memory_mb": 16384.0,
    "used_memory_bytes": 8589934592,
    "used_memory_mb": 8192.0,
    "free_memory_bytes": 8589934592,
    "free_memory_mb": 8192.0,
    "memory_percent": 50.0,
    "cpu_count": 8,
    "cpu_usage_percent": 15.5
  },
  "segment_drift": {
    "checked": 1284,
    "mismatched": 0,
    "worst_delta_ms": 42
  },
  "timestamp": 1702834567
}
```

## Инвариант нарезки (`segment_drift`)

- **checked** — сколько отданных HLS-сегментов сверено с картой сегментов
- **mismatched** — у скольких фактическая длительность разошлась с обещанной в плейлисте сильнее допуска
- **worst_delta_ms** — худшее расхождение в миллисекундах

`mismatched > 0` — это баг в нарезке, даже если жалоб от пользователей нет.

## Метрики процесса

- **memory_bytes** - Использование памяти процессом в байтах
- **memory_mb** - Использование памяти процессом в мегабайтах
- **cpu_percent** - Использование CPU процессом в процентах
- **uptime_seconds** - Время работы процесса в секундах
- **open_files** - Количество открытых файлов (недоступно в sysinfo 0.30)

## Системные метрики

- **total_memory_bytes** - Общая память системы в байтах
- **used_memory_bytes** - Используемая память системы в байтах
- **free_memory_bytes** - Свободная память системы в байтах
- **memory_percent** - Использование памяти системой в процентах
- **cpu_count** - Количество CPU ядер
- **cpu_usage_percent** - Средняя загрузка CPU в процентах

## Автоматическое логирование

Сервер автоматически логирует метрики каждую минуту в формате:

```
Метрики: память процесса=50.00MB, CPU процесса=2.5%, память системы=50.0% (8192.00MB/16384.00MB), CPU системы=15.5%
```

## Мониторинг больших файлов

При просмотре больших видеофайлов рекомендуется:

1. Отслеживать метрики через `/api/metrics`
2. Проверять логи на предмет роста использования памяти
3. При превышении лимитов памяти - перезапустить сервер

## Пример использования

```bash
# Получить текущие метрики
curl http://localhost:4000/api/metrics | jq

# Мониторинг в реальном времени
watch -n 5 'curl -s http://localhost:4000/api/metrics | jq ".process.memory_mb"'
```
